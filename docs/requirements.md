# 业务需求

## 产品目标

帮助用户把分散在多个位置的照片、视频和文档整理为可核对、可重复执行的归档库，尽量避免重复副本、错误归档和源数据损失。产品面向个人媒体库，包含数百 GB 数据和大量文件的使用场景。

## 当前能力

### 来源与文件范围

- 处理一个或多个本地文件、目录和 SMB 网络共享来源，并允许一次任务混用多个来源。
- 默认整理照片和视频，也允许用户显式纳入其他文件。
- 提供独立的文档整理能力，仅处理支持的文档，不影响媒体和未知文件。

### 整理与判重

- 按内容识别重复文件，目标库已有相同内容时不重复保存。
- 支持复制和移动；复制不改变源，移动在成功归档或确认重复后移除相应源文件。
- 按可配置的年月日、相机信息和有意义目录段归档媒体。
- 按创建时间及可选内容类目归档文档；无法可靠分类时放入未分类位置。
- 生成重复文件审查结果，由用户决定最终删除项，不自动执行审查脚本。
- 识别含文字的图片并单独整理。

### 时间与核对

- 优先采用可信的拍摄或创建时间；缺少可靠信息时，结合文件名和文件时间作出可解释的归档决定。
- 对时间冲突、低置信度结果和可能错误的相机时钟给出提示，不静默掩盖重要分歧。
- 在正式整理前预演结果，并核对预测位置、目标库重复情况和潜在异常。
- 核对过程不修改源或归档媒体；修复时间信息和实际移动由用户另行决定。
- 输出处理结果、失败信息和必要的人工审查材料。

## 数据安全要求

- 除用户显式指定的报告外，预演不得写入目标或删除源文件。
- 不得覆盖目标库中同名但内容不同的文件，包括并行处理和文件名大小写不同的情况。
- 被过滤或跳过的文件不得因“与目标重复”而被删除。
- 来源与输出重叠时，不得把已归档内容再次当作待删源处理。
- 移动操作只有在目标写入成功或重复关系确认后才能删除源；复制成功但删源失败时必须明确报告。
- 重复执行同一任务不应产生正常重复副本，也不应重复删除已经处理的源。
- 中断或部分失败必须可观察；无法自动恢复的情况应提供人工核对和恢复指引，不得宣称绝对安全或无遗漏。
- 涉及覆盖时间信息、删除文件或正式移动的决定，必须由用户明确确认。

## 验收标准

- 用包含不同内容、完全相同内容、同名不同内容及不同大小写文件名的样本验证：目标无覆盖、无异常重复，结果计数与文件现状一致。
- 用包含照片、视频、文档、空文件、不可读文件和跳过类型的样本验证：每类文件的处理结果符合用户选择，失败和跳过可见。
- 用包含可信拍摄时间、缺失时间和冲突时间的样本验证：归档位置可解释，冲突能够被发现。
- 对复制和移动分别验证预演不改变文件；正式执行后，源与目标状态符合所选操作。
- 对同一任务重复执行，验证目标不增加正常重复副本，失败项可在排除原因后重试。
- 对含文字图片和文档分类进行人工抽样，确认结果便于复核，不把自动判断当作不可更改的结论。
- 对大型库和远端来源观察内存、日志和失败情况；达到环境限制时应明确停止或报告，而不是静默遗漏。

## 未满足需求

- 提供增量处理，减少重复执行时对未变化文件的重复扫描和判重。
- 降低远端大文件读写整体占用内存造成的限制，使超大文件也能可靠处理。
- 明确扫描并报告本地隐藏文件，避免用户对处理范围产生误解。
- 完善远端目标写入的防覆盖与冲突保护，使外部并发或重复操作也不能破坏已有文件。
- 在操作系统时区与归档配置时区不同时，仍能正确核对文件修改时间。
- 外部证据工具执行失败或日期不符合真实日历时，应自动停止并明确标记证据不完整，不能继续生成可执行修复建议。
- 视频时间修复建议应覆盖所有仍存在的相关时间字段，避免旧的高优先级值继续决定归档位置。

## 待确认需求

- 确认 QQ 导出及括号内时间的真实语义。它们目前可用于缺少更可靠时间时的归档，但不会仅因与文件时间接近就替换已有拍摄时间；纠正规则仍需真实样本验证。
- 确认 iPhone 编辑导出视频在何种情况下仍可能按导出时间而非原始拍摄时间归档。
- 验证 SMB 网络共享在真实环境中的完整兼容性，包括中文、空格和异常断连场景。
